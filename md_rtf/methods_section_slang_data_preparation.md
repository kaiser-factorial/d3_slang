# Methods: Data Preparation And Annotation

This project compares a 2020-2025 Gen-Z slang dataset with a 2010 Twitter slang dataset. Because the two datasets were not structurally comparable at the start, the 2010 dataset required substantial cleaning, annotation, and filtering before analysis.

First, the 2010 Twitter dataset was cleaned and standardized. The raw file contained malformed headers, extra unnamed columns, junk rows, and separate `year`, `month`, and `day` fields. These issues were corrected by removing malformed records, normalizing the schema, and combining the date fields into a single `date` column. The cleaned dataset preserved 57,345 usable tweet rows.

Next, reference vocabularies were extracted from the Gen-Z dataset in order to guide annotation. Three reference sets were created: a `(slang_term, term_category, term_meaning)` lookup table, a list of unique `term_category` values, and a list of unique `usage_context` values. These references were used as a taxonomy guide rather than as a direct lookup source, since the 2010 and 2020-2025 vocabularies had little direct overlap.

To enrich the 2010 data, a term-level annotation table was created with one row per unique slang term. Each term was annotated with a fixed `term_meaning` and `term_category`. The guiding principle was that `term_category` should describe the lexical property of the term itself, not vary from tweet to tweet. Gen-Z categories were reused when they fit well, but new categories were introduced when forcing a match would weaken the analysis. Acronyms were standardized so that `term_meaning` began with the quoted full expansion when appropriate.

The term-level annotation process was iterative and collaborative. Candidate meanings and categories were first researched using dictionary and slang references, then checked against tweet examples only when disambiguation was necessary. Ambiguous cases were additionally reviewed through delegated subagent checks, and proposed batches were then presented for manual human review before being finalized. This human-in-the-loop workflow led to several meaningful revisions, including changes to entries such as `gnarly`, `badass`, `twit`, and `thirsty`.

After term-level annotation was complete, the annotations were propagated back onto the 2010 tweet rows. This added `term_meaning` and `term_category` to each tweet. A second tweet-level annotation stage then added `usage_context` and `is_ironic`. The `usage_context` field was treated as a broader tweet/post context rather than a narrow word-sense label, based partly on how the Gen-Z dataset appeared to use that field. Annotation guidelines were developed first, and additional context labels were introduced where needed for the 2010 material, such as `article_sharing`, `technology_discussion`, `sports_discussion`, and `sexual_context`.

Tweet-level annotation also used a multi-review workflow. One set of subagents reviewed the active batch, another trailed the previous batch, and irony judgments were audited across categories. This process was repeated category-by-category until the full 2010 tweet set had valid `usage_context` and `is_ironic` labels.

The 2010 term table was then further enriched with `origin_platform` and `origin_platform_confidence`. This involved researching the likely origin or diffusion channel of each term using sources such as Merriam-Webster, Wiktionary, Dictionary.com, Green’s Dictionary of Slang, Know Your Meme, and related references. A separate provenance file was maintained to document each term’s origin label, confidence level, source, and notes.

Finally, a row-level filtering stage was applied to remove tweets where the target token appeared but was not actually being used as slang in a useful analytic sense. This step did not simply remove entire `usage_context` categories. Instead, `usage_context` was used as a triage device, and rows were reviewed according to whether the target word functioned as slang, informal lexical material, or meaningful in-group jargon. Product listings, title shells, media references, file-format references, literal non-slang uses, and certain handle/name collisions were excluded. Domain-specific jargon and metalinguistic discussion of slang terms were often retained when they were still relevant to slang analysis.

The result of this pipeline was a filtered 2010 analysis dataset with 36,005 rows. The final analysis-ready file includes the following columns: `word`, `id`, `date`, `text`, `author_id`, `term_meaning`, `term_category`, `usage_context`, and `is_ironic`. This transformed the original 2010 dataset from a noisy term-occurrence file into a structured comparative dataset that is much closer to the Gen-Z dataset in analytical usefulness.
